# 必读 04：中文输出硬约束

> **目的**：汇总报告"威胁分析报告中文、人类友好"（来自原始规范）。

## 一、规则

| 内容类型 | 语言 | 示例 |
|----------|------|------|
| **叙述性内容** | 必须中文 | 执行摘要、风险描述、规则说明 |
| **代码** | 英文 | Java、SQL、Python |
| **字段名 / JSON key** | 英文 | `"vuln_type"`, `"evidence"` |
| **类型枚举值** | 英文 | `"SQL_INJECTION"`, `"HIGH"` |
| **文件名** | 中文可 | 报告标题、章节标题 |
| **日志消息** | 中文 | 给人工看的诊断信息 |

## 二、subagent prompt 强制项

每个 FWD subagent 的 prompt 必须包含：

```markdown
## 输出语言
- 所有叙述性内容用中文
- JSON 字段名、枚举值用英文
- 报告中的 SQL/代码示例保留原始英文
- 评分理由、判断依据用中文
```

## 三、错误示例 ❌

```json
{
  "summary": "This endpoint has SQL injection vulnerability due to string concatenation in DAO layer"
}
```

## 四、正确示例 ✅

```json
{
  "summary": "该端点存在 SQL 注入漏洞：DAO 层使用字符串拼接而非参数化查询，攻击者可通过 name 参数注入 SQL 片段",
  "vuln_type": "SQL_INJECTION",
  "severity": "CRITICAL"
}
```

## 五、汇总报告要求

`loop_audit/终态汇总报告.md` 必须是：
- 中文叙述
- 人类可读
- 威胁分析部分展开论述（不只列条目）
- 漏洞分级严格（致命/严重/中危/低危）
- API 报告完整无缺

## 六、检测

- subagent 输出的 `summary` 字段如果 > 50% 英文 → 重做
- 评分 subagent 发现英文叙述 → 扣 5 分（格式人类友好项）
- 端到端审计前 5 个 finding 抽样检查 1 次
