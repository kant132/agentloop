# 历史审计记录

> 历次扫描的 findings 沉淀。新一轮 Loop 启动时必读，避免重复发现。

## 一、记录格式

每次 Loop 完成后追加：

```markdown
## {日期} - {round} 轮

- **总 finding 数**：{N}
- **致命 / 严重 / 中危 / 低危**：{x} / {y} / {z} / {w}
- **PoC 通过率**：{pct}%
- **项目特定发现**：
  - {新发现的业务规则特例}
  - {新发现的自定义注解}
  - {新发现的误报模式}
- **未解决的旧 finding**：
  - {chainId}：{原因}
- **建议优化**：
  - {剪枝规则更新建议}
  - {类型库更新建议}
```

## 二、记录样例

## 2026-06-12 - 第 1 轮

- **总 finding 数**：42
- **致命 / 严重 / 中危 / 低危**：3 / 7 / 18 / 14
- **PoC 通过率**：85%
- **项目特定发现**：
  - 自定义注解 `@Inner` 标记内部接口（应视为鉴权）
  - MyBatisProvider 中 `${}` 实际是被 provider 内部 `#{}` 转义，是误报
- **未解决的旧 finding**：
  - chainId-007：环境不可达，PoC 跳过
- **建议优化**：
  - 剪枝规则加：MyBatisProvider 方法体非最终 sink
  - 类型库补：项目特有的 `@Inner` 鉴权等价物
