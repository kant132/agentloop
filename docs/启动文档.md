# WSL Ubuntu 启动文档

> 本文档说明如何进入 WSL Ubuntu 环境并验证开发工具链。
> 适用环境：WSL2 + Ubuntu 24.04 + nvm + Node.js LTS + opencode CLI

---

## 工具链版本

| 工具 | 版本 |
|---|---|
| Ubuntu | 24.04.1 LTS |
| nvm | 0.40.1 |
| Node.js | v24.17.0 (LTS) |
| npm | 11.13.0 |
| opencode | 1.17.9 |

---

## 一、进入 WSL Ubuntu

以下四种方式任选其一。

### 方式 1：命令行（推荐）

打开 Windows PowerShell 或 Windows Terminal，输入：

```powershell
wsl -d Ubuntu
```

> 如果已将 Ubuntu 设为默认发行版（见下文），直接输入 `wsl` 即可。

### 方式 2：设为默认发行版

```powershell
wsl --set-default Ubuntu
```

设置后，以后直接输入 `wsl` 就进入 Ubuntu：

```powershell
wsl
```

查看当前默认发行版：

```powershell
wsl -l -v
```

名称前带 `*` 的即为默认发行版。

### 方式 3：开始菜单

搜索「Ubuntu」，点击图标直接打开 Ubuntu 终端窗口。

### 方式 4：Windows Terminal 标签页

Windows Terminal 顶部标签栏的下拉箭头 ▾ 中选择「Ubuntu」。

## 二、验证工具链

进入 Ubuntu 终端后，执行以下命令确认所有工具就绪：

```bash
node --version
npm --version
opencode --version
```

预期输出：

```
v24.17.0
11.13.0
1.17.9
```

查看命令路径：

```bash
which node npm opencode
```

预期输出（均在 `/home/wq/.nvm/versions/node/v24.17.0/bin/` 下）：

```
/home/wq/.nvm/versions/node/v24.17.0/bin/node
/home/wq/.nvm/versions/node/v24.17.0/bin/npm
/home/wq/.nvm/versions/node/v24.17.0/bin/opencode
```

> 如果 `which` 返回 `/mnt/c/...` 开头的路径，说明使用了 Windows 的 Node.js，请确认是通过交互式终端进入（而非 `wsl -d Ubuntu -- bash -lc`），交互式终端会自动加载 `~/.bashrc` 中的 nvm 配置。

## 三、启动 opencode

```bash
opencode
```

这会启动 opencode CLI 交互界面。

查看帮助：

```bash
opencode --help
```

查看版本：

```bash
opencode --version
```

## 四、常用操作

### Node.js 版本管理

```bash
# 查看当前使用的版本
node --version

# 查看已安装的所有版本
nvm ls

# 安装其他版本
nvm install 20          # 安装 Node.js 20
nvm install --lts       # 安装最新 LTS

# 切换版本
nvm use 20
nvm use --lts

# 设置默认版本（新终端自动使用）
nvm alias default 20
```

### npm 全局包管理

```bash
# 查看已安装的全局包
npm list -g --depth=0

# 安装全局包
npm install -g <包名>

# 卸载全局包
npm uninstall -g <包名>
```

### 退出 WSL

```bash
exit
```

或按 `Ctrl + D`。

## 五、文件系统互访

### WSL 中访问 Windows 文件

Windows 的磁盘挂载在 `/mnt/` 下：

```bash
# C 盘
ls /mnt/c/

# D 盘
ls /mnt/d/

# 访问 D:\agentloop\docs
ls /mnt/d/agentloop/docs/
```

### Windows 中访问 WSL 文件

在文件资源管理器地址栏输入：

```
\\wsl$\Ubuntu\home\wq
```

或通过命令行：

```powershell
explorer.exe \\wsl$\Ubuntu\home\wq
```

## 六、故障排查

### 问题：进入终端后 node/npm/opencode 命令不存在

**原因**：`~/.bashrc` 中的 nvm 配置未正确加载。

**排查步骤**：

1. 检查 `.bashrc` 是否包含 nvm 配置：
   ```bash
   grep nvm ~/.bashrc
   ```

2. 如无输出，手动添加：
   ```bash
   cat >> ~/.bashrc << 'EOF'
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
   [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"
   EOF
   ```

3. 重新加载：
   ```bash
   source ~/.bashrc
   ```

4. 手动加载 nvm 并切换 Node.js：
   ```bash
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
   nvm use --lts
   ```

### 问题：wsl 命令提示 WSL 1 not supported

这是 nvm 安装脚本的误报。确认实际 WSL 版本：

```bash
cat /proc/version
```

输出包含 `microsoft-standard-WSL2` 即为 WSL2，可忽略该提示。

### 问题：docker-desktop 发行版干扰

如果 `wsl -l -v` 显示 `docker-desktop` 且为默认发行版，`wsl` 命令会进入它而非 Ubuntu。

**解决**：将 Ubuntu 设为默认：

```powershell
wsl --set-default Ubuntu
```

## 七、快速启动清单

新环境部署后，执行以下命令一次性验证：

```bash
echo "=== WSL Version ===" && cat /proc/version | grep -o 'WSL[0-9]'
echo "=== nvm ==="        && nvm --version
echo "=== Node.js ==="    && node --version
echo "=== npm ==="        && npm --version
echo "=== opencode ==="   && opencode --version
echo "=== Paths ==="      && which node npm opencode
```

全部通过即环境就绪。

## 八、Windows ↔ WSL 配置共享方案

WSL Ubuntu 中的 opencode 与 Windows 侧共享 skills 和配置，实现双环境无缝切换。

### 共享架构

```
Windows (C:\Users\Administrator\)          WSL Ubuntu (/home/wq/)
├── .agents/skills/        ──symlink──>    ~/.agents → /mnt/c/.../.agents
├── .claude/skills/         ──symlink──>    ~/.claude → /mnt/c/.../.claude
├── .claude/CLAUDE.md       ──symlink──>    (含在 ~/.claude 中)
├── .opencode/skill/       ──symlink──>    ~/.opencode/skill → /mnt/c/.../.opencode/skill
├── .opencode/plugins/     ──symlink──>    ~/.opencode/plugins → /mnt/c/.../.opencode/plugins
├── .config/opencode/skills/ ─symlink──>   ~/.config/opencode/skills → /mnt/c/.../.config/opencode/skills
├── .config/opencode/opencode.json          ~/.config/opencode/opencode.json (复制+适配)
├── .config/opencode/oh-my-openagent.jsonc  ~/.config/opencode/oh-my-openagent.jsonc (复制)
├── .config/opencode/tui.json               ~/.config/opencode/tui.json (复制)
└── .opencode/opencode.json                 ~/.opencode/opencode.json (复制)
```

### 共享方式说明

| 资源 | 方式 | 原因 |
|---|---|---|
| Skills 目录 (4个) | 符号链接 | 纯 Markdown 文档，平台无关，自动同步 |
| CLAUDE.md | 符号链接 (含在 ~/.claude 中) | 纯文本，平台无关 |
| graphify 插件 | 符号链接 | JS 代码，平台无关 |
| opencode.json | 复制 + 适配 | MCP 命令需改写（见下文） |
| oh-my-openagent.jsonc | 复制 | 模型映射，无平台差异 |
| tui.json | 复制 | TUI 配置，无平台差异 |
| .opencode/opencode.json | 复制 | 插件配置，无平台差异 |

### MCP 命令适配

Windows 的 `opencode.json` 中 MCP 服务器使用 `cmd /c npx` 调用，WSL Ubuntu 中需改为直接 `npx`：

| MCP 服务器 | Windows 命令 | WSL Linux 命令 |
|---|---|---|
| context7 | `["cmd","/c","npx","-y","@upstash/context7-mcp"]` | `["npx","-y","@upstash/context7-mcp"]` |
| memory | `["cmd","/c","npx","-y","@modelcontextprotocol/server-memory"]` | `["npx","-y","@modelcontextprotocol/server-memory"]` |
| sequential-thinking | `["cmd","/c","npx","-y","@modelcontextprotocol/server-sequential-thinking"]` | `["npx","-y","@modelcontextprotocol/server-sequential-thinking"]` |
| wechat | `["cmd","/c","bunx","-y","mcp-wechat-server"]` | `["bunx","-y","mcp-wechat-server"]` |
| playwright | `"npx"` (无 cmd) | 不变 |
| codegraph | `["codegraph","serve","--mcp"]` | 不变 |

### 配置文件位置

| 配置文件 | Windows 路径 | WSL 路径 |
|---|---|---|
| 主配置 | `C:\Users\Administrator\.config\opencode\opencode.json` | `~/.config/opencode/opencode.json` |
| Agent 模型映射 | `C:\Users\Administrator\.config\opencode\oh-my-openagent.jsonc` | `~/.config/opencode/oh-my-openagent.jsonc` |
| TUI 配置 | `C:\Users\Administrator\.config\opencode\tui.json` | `~/.config/opencode/tui.json` |
| 插件配置 | `C:\Users\Administrator\.opencode\opencode.json` | `~/.opencode/opencode.json` |
| 指令文件 | `C:\Users\Administrator\.claude\CLAUDE.md` | `~/.claude/CLAUDE.md` (符号链接) |

### 已配置的模型 Provider

| Provider | 模型 | 用途 |
|---|---|---|
| Bailian (百炼) | glm-5.1, glm-5.2, qwen3.6-flash, qwen3.6-plus, qwen3.7-max | 主力模型（glm-5.2 用于 sisyphus/oracle/metis 等） |
| DeepSeek | deepseek-v4-flash, deepseek-v4-pro | 备选 |
| MiniMax | MiniMax-M2.7, MiniMax-M3 | 备选 |

### Skills 共享验证

```bash
# 查看所有可用的 skills
find ~/.agents/skills/ ~/.claude/skills/ ~/.opencode/skill/ ~/.config/opencode/skills/ -name SKILL.md 2>/dev/null | wc -l
# 预期输出: 213

# 查看各目录的 skills 数量
ls ~/.agents/skills/ | wc -l      # ~160+ (主体 skills)
ls ~/.claude/skills/ | wc -l      # ~140 (Claude skills)
ls ~/.opencode/skill/ | wc -l     # ~19 (java/security skills)
ls ~/.config/opencode/skills/    # graphify
```

### 注意事项

1. **Skills 自动同步**：在 Windows 侧新增/修改 skills 后，WSL 侧通过符号链接立即可见，无需手动同步。

2. **配置文件不同步**：`opencode.json`、`oh-my-openagent.jsonc`、`tui.json` 是独立复制的。如果 Windows 侧修改了这些配置，需手动同步到 WSL：
   ```bash
   cp /mnt/c/Users/Administrator/.config/opencode/oh-my-openagent.jsonc ~/.config/opencode/
   cp /mnt/c/Users/Administrator/.config/opencode/tui.json ~/.config/opencode/
   # opencode.json 需手动适配 MCP 命令后再复制
   ```

3. **MCP 服务器依赖**：WSL 中需单独安装 `codegraph`、`bun`(bunx) 等工具才能使用对应的 MCP 服务器。未安装的 MCP 服务器会在启动时报错但不影响其他功能。

4. **Windows 配置未被修改**：Windows 侧的 `opencode.json` 仍保持 `cmd /c` 语法不变，两套配置完全独立。
