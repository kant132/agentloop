## 前置条件

1. 已安装 WSL2 并启用 Ubuntu 发行版
2. Ubuntu 发行版已初始化（首次启动时创建用户）
3. 网络可访问 GitHub 和 npm 官方源

确认 WSL 版本（在 Windows PowerShell 中执行）：

```powershell
wsl -l -v
```

输出应包含 Ubuntu 且 VERSION 列为 2：

```
  NAME      STATE     VERSION
  Ubuntu    Stopped   2
```

## 第一步：安装 nvm（Node Version Manager）

nvm 用于管理多个 Node.js 版本，推荐在 Linux 侧安装原生 nvm，避免使用 Windows 的 Node.js（通过 `/mnt/c/Program Files/nodejs/` 互操作会有路径、权限、原生模块兼容性问题）。

### 安装命令

```bash
# 在 WSL Ubuntu 终端中执行
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
```

### 验证

```bash
# 重新加载 nvm（新开终端会自动加载，此处手动加载用于验证）
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
nvm --version
```

预期输出：

```
0.40.1
```

### 安装后说明

- nvm 安装到 `/home/wq/.nvm/` 目录
- 自动在 `~/.bashrc` 末尾追加以下配置：
  ```bash
  export NVM_DIR="$HOME/.nvm"
  [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
  [ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
  ```

> **已知提示**：安装时可能出现 `WSL 1 is not supported. Please upgrade to WSL 2 or above.` 的误报。实际内核版本为 `microsoft-standard-WSL2`，此提示不影响 nvm 正常工作，可忽略。

## 第二步：安装 Node.js LTS

```bash
# 在 WSL Ubuntu 终端中执行（nvm 已通过 .bashrc 自动加载）
nvm install --lts
```

### 验证

```bash
node --version
npm --version
which node
which npm
```

预期输出：

```
v24.17.0
11.13.0
/home/wq/.nvm/versions/node/v24.17.0/bin/node
/home/wq/.nvm/versions/node/v24.17.0/bin/npm
```

### 说明

- `nvm install --lts` 安装最新 LTS 版本并自动设为当前使用版本
- 同时创建 default alias：`default -> lts/* -> v24.17.0`
- 新开终端会自动加载该版本，无需手动 `nvm use`

## 第三步：安装 opencode CLI

### 正确的包名

npm 上的 opencode CLI 包名是 **`opencode-ai`**（无 `@scope`）。

> **重要**：不要安装 `@opencode-ai/cli`，那是另一个工具，其 bin 命令名是 `lildax` 而非 `opencode`。

### 安装命令

```bash
npm install -g opencode-ai
```

### 验证

```bash
opencode --version
which opencode
```

预期输出：

```
1.17.9
/home/wq/.nvm/versions/node/v24.17.0/bin/opencode
```

### 关于 `opencode.exe` 文件名

安装后 bin 软链接指向 `opencode.exe`，文件名带 `.exe` 后缀容易误解为 Windows 可执行文件。实际用 `file` 命令验证：

```bash
file /home/wq/.nvm/versions/node/v24.17.0/lib/node_modules/opencode-ai/bin/opencode.exe
```

输出：

```
ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked,
interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 3.2.0, not stripped
```

这是原生 Linux ELF 二进制文件，`.exe` 只是包的命名习惯，在 Linux 下原生运行无问题。

## 常见问题

### Q1: which node 返回 `/mnt/c/Program Files/nodejs/...`

这说明 WSL 的 PATH 中 Windows 的 Node.js 路径排在前面，使用了 Windows 的 Node.js 而非 Linux 原生的。

**解决**：按本文档安装 nvm + Node.js 后，Linux 原生版本会在交互式终端中自动生效（nvm 会在 PATH 前部插入 Linux node 路径）。如仍有问题，检查 `~/.bashrc` 是否包含 nvm 加载配置。

### Q2: npm install -g 后命令找不到

如果 `which <命令>` 返回 `/mnt/c/Users/.../AppData/Roaming/npm/...`，说明 Windows npm 全局包路径污染了 PATH。

**解决**：确保通过交互式终端（读取 `.bashrc`）执行命令，nvm 管理的 Linux node 路径会优先。

### Q3: nvm: command not found（非交互式 shell）

在 `bash -lc` 或脚本中执行时 nvm 可能未加载。

**解决**：手动 source nvm：

```bash
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
```

### Q4: 如何切换 Node.js 版本

```bash
# 安装其他版本
nvm install 20          # 安装 Node.js 20 最新版
nvm install 22          # 安装 Node.js 22 最新版

# 切换版本
nvm use 20
nvm use --lts

# 查看已安装版本
nvm ls

# 设置默认版本
nvm alias default 20
```

## 卸载方法

如需清理，按以下步骤卸载：

```bash
# 1. 卸载 opencode
npm uninstall -g opencode-ai

# 2. 卸载 Node.js（通过 nvm）
nvm uninstall 24.17.0

# 3. 卸载 nvm
rm -rf "$HOME/.nvm"
# 手动删除 ~/.bashrc 中的 nvm 相关行（最后三行）
```
