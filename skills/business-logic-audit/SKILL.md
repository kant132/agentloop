# 业务逻辑漏洞审计

专注：无明确技术 sink 但业务规则本身有缺陷——IDOR、竞态、状态绕过、数值溢出、mass assignment、越权。

## 思路

业务逻辑漏洞不在 filter 不在 sanitizer，在"业务规则没覆盖到的路径"。核心问题：客户端能发任何请求，服务端是否真的校验了每个业务约束？

## 步骤（3 步强制）

### 1. 状态流还原（arthas）

用 `watch`/`trace` 追踪业务流程实际执行路径：
- 每步状态变更是否有服务端校验
- 业务步骤能否被跳过（直接调后续步骤接口）
- 幂等性：多次执行结果是否一致

### 2. 边界与约束审计

用 arthas 验证每个约束的实际执行：
- 数值边界：最小/最大/精度/单位一致
- 频率限制：是否有效、可否并发绕过
- 业务规则：后端是否做了与前端相同的校验
- 状态机：非法跳跃可能
- 并发：多实例操作同一资源
- 时间窗口：前后端一致校验

### 3. 构造与验证

针对薄弱约束构造最小 payload → curl 并发/边界/越权 ID → arthas watch → 确认约束确实被绕过。失败时记录原因。

## 常见坑

### 竞态条件（TOCTOU）
- 下单到扣款之间的时间窗
- 并发请求的重复执行
- 幂等性缺失：重复扣款/发货
- 分布式锁粒度或漏用

### 流程绕过
- 支付步骤被绕过
- 多步流程中某环节失败后未回滚
- 通过内部接口绕过审核
- 状态机跳跃式更新

### 状态篡改
- 客户端携带状态参数未校验
- 状态字段无鉴权保护
- 历史状态可重新触发

### 数值计算
- 数据类型和范围、浮点精度（BigDecimal vs float）
- 金额边界：负数/零/超大值
- 优惠券叠加规则、金额一致性、货币单位统一

### 批量赋值 / 越权
- 批量接口写不该由客户端控制的字段
- IDOR 遍历、管理接口鉴权缺失

### 频率 / 额度
- 限制维度不全（只 IP 不只用户/反之）
- 跨实例计数不同步

### 时间类
- 活动时间校验绕过、时区处理冲突

## 禁止行为

- 只看前端校验不验证后端
- 只测正常流程不测异常/并发/边界
- 假设频率控制/额度限制生效而不验证
- 忽略任何字段的客户端可控性
- 假设状态机只有合法转移路径
