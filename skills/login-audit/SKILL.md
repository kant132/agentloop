# 登录接口漏洞审计

适用范围：登录接口（/login、/auth、/signin、/token）及业务中的登录验证环节（SSO 回调、MFA 验证）。

## 思路

登录是攻击面最大的端点——接收明文凭据、产生会话、区分用户存在性。核心问题：凭证如何比对？失败信息泄露了多少？防御机制是否真的跨分布式生效？

## 步骤（4 步强制）

### 1. 登录流观察（arthas）

`watch` 登录处理方法，观察：
- 实际参数（用户名/密码/验证码/其他字段）
- 凭证校验完整执行路径
- 成功/失败的返回差异（响应体、状态码、响应时间）

### 2. 凭证校验审计

- 比对方式：明文/哈希/加密？constant-time？
- 失败时是否暴露原因（用户名不存在 vs 密码错误）
- 默认凭据/测试账号

### 3. 反暴力攻击机制（arthas 验证实际有效性）

- 频率限制：是否跨 IP/用户/设备，可否代理绕过
- 验证码：后端校验 vs 前端、复用、绕过、参数篡改
- 账号锁定：临时 vs 永久？锁定范围（账号/IP/设备）
- 找回密码：可否被绕过

### 4. 会话与凭证管理

- 登录后 regenerate session ID（防 fixation）
- token 生成：随机性/强度/有效期/安全属性(Secure/HttpOnly/SameSite)
- 多设备互踢
- 凭证是否在响应中泄露（URL/日志）

## 常见坑

### 响应差异 → 用户枚举
- 不同错误信息、响应时间(timing attack)、状态码

### 凭证传输与存储
- 密码传输未加密
- 存储: 明文/MD5/SHA 无 salt
- 只比对哈希前 N 位

### 反暴力机制失效
- 失败计数成功登录后清零 → 每次成功可重放
- X-Forwarded-For 伪造绕过 IP 白名单
- 分布式环境计数不同步

### 会话漏洞
- 不刷新 session ID → fixation
- token 有效期过长或无过期
- 登出未真正使 token 失效

### MFA 绕过
- 绕过 MFA 直接调"验证通过"接口
- 验证码长度太短(4-6位)可暴力破解
- 备用恢复渠道频率限制缺失

### 其他
- "记住我" token 可预测
- OAuth 回调未验证 state/nonce
- 响应含敏感信息（用户 ID/角色/内部字段）
- 日志记录密码

## 禁止行为

- 不实际触发登录流就下结论
- 只测正常路径不测异常路径
- 忽略响应差异（时间和状态码）
- 只验证登录成功不测试失败路径
