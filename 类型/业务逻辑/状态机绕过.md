# 状态机绕过

> **类型 ID**: `AP-BIZ-STATE`
> **轨道**: FWD-D
> **业务域**: 9 类必查之一

## 一、定义

业务流程有多个状态（如订单：待支付 → 已支付 → 已发货 → 已签收），但服务端不校验当前状态是否允许状态转换，攻击者可以跳过中间步骤。

## 二、典型场景

```java
// ❌ 不校验前置状态
@PostMapping("/order/refund")
public Result refund(@RequestBody RefundRequest req) {
    Order order = orderService.findById(req.getOrderId());
    order.setStatus("REFUNDED");  // 任意状态都可退款
    return orderService.save(order);
}
```

## 三、检测启发式

### 3.1 关键信号
- 端点含 `refund` / `cancel` / `confirm` / `ship` / `complete`
- 方法内有 `setStatus(...)` 或类似
- **缺失**：`switch (currentStatus)` 校验合法转换

### 3.2 AST 模式
```yaml
pattern: $ORDER.setStatus($NEW_STATUS)
# 缺：switch ($ORDER.getStatus()) { case ... }
```

## 四、合法状态转换模板

```
PENDING → PAID → SHIPPED → DELIVERED → CONFIRMED
PENDING → CANCELED
PAID → REFUNDED (with time limit)
```

每个状态转换前必查 `current_status` 是否允许。

## 五、误报模式

- 已用状态机框架（Spring StateMachine）
- 业务流程只有单一状态
- 转换校验在统一 Service 中（FWD 跨方法追踪）
