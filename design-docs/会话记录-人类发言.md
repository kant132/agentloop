老板（主 agent）[skills/java-whitebox-loop]
负责整个 loop：端点枚举、给每个端点派主管、对账、抽检、评分、收敛判断、拒绝或接受主管提交的结果、自我反思形成经验。只有老板能修改执行路径、新增脚本、调整流程。任何对工具本身的修改，由老板单独派一个临时工具 agent 去实现，避免主流程被污染，且修改必须具有普遍性、不能对当前项目过拟合。

主管（每端点派的决策 agent）
老板为每个待审计端点派一个主管。主管拿到端点通过分析师遍历调用链，每一条调用链都决定要派哪些专家、派几次、按什么顺序。专家产出的结果由主管用安审视角（Chris Anley、吴翰清、尹毅）质疑，不满意就拒回重做。专家执行中若认为需要其他专家协作，先回主管说明理由，主管决策后记录这次协调判断——如果确实是主管之前漏判，沉淀为普遍性经验供后续主管自我修正。主管在 experts 全部结束后汇总该端点的 findings，更新缓存状态，向老板汇报。

分析师（调用链分析 agent，由主管派）[skills/call-chain-audit-thinking]
给定一条调用链，输出 5 维思考：入参溯源、消毒验证、权限归属、分支绕过、信息泄露。只输出结构化分析结果，不直接报告漏洞，由主管决定后续派哪些挖洞专家。

挖洞专家（每个专家只专注一类漏洞，由主管派）
- 注入类 [skills/injection-audit]：SQL/CMD/XXE/反序列化/表达式/SSTI/LDAP/NoSQL
- 业务逻辑类 [skills/business-logic-audit]：竞态/流程绕过/状态篡改/数值边界/批量赋值/越权
- 文件操作类 [skills/file-audit]：上传/下载/读取/删除/临时文件/压缩包/路径穿越
- 认证鉴权类 [skills/auth-chain-audit]：Filter 链路径归一化差异/校验逻辑缺陷/JWT/SSO
- 登录接口类 [skills/login-audit]：凭证处理/暴力破解/会话劫持/MFA 绕过

每个挖洞专家必须遵循统一输出格式（由主管可改）：执行过程 + 执行结果 + finding。finding 字段统一（chain_id / endpoint / fqn / vuln_type / severity / evidence / summary / judgment / poc_status），主管可拒绝不符合格式的产出。
