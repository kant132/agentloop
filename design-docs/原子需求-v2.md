## Phase 0 — 准备

### AR-01 三核心工具不可降级
- 描述：codegraph / ast-grep / Memurai 任一不可用，立即 exit 2，不进入降级模式。
- 输入：`projects/{group_id}/preset.json`（含 `projectRoot`、`codegraphDb`、`groupId`、`loopDir`）。
- 输出：进程 exit code（0 表示通过，2 表示缺失并打印缺失清单）。无文件产物。
- 实现锚点：`scripts/audit/check_core_tools.py`
- 状态：✅

### AR-02 清空旧缓存保留知识
- 描述：每轮启动清空 `{groupId}:*` 键，保留 `{groupId}:knowledge:*` 跨轮知识。
- 输入：`groupId`（来自 preset.json）。
- 输出：Memurai 中 `{groupId}:*` 键全部删除，`{groupId}:knowledge:*` 键保持。`.preflight/status.txt` 写入就绪状态。
- 实现锚点：`scripts/audit/cross-agent-50r.py`（启动段）+ `scripts/redis/memurai_client.py`
- 状态：✅

## Phase 1 — 暴露面采集

### AR-03 8 类资产采集
- 描述：route / config / codegraph / auth_code / sensitive_info / waf / db_schema / env_filter 各自独立采集，互不阻塞。
- 输入：`project_root` + `group_id` + `codegraph_db`（可选）+ `ssh_target`（可选）。
- 输出：`{loop_audit_dir}/exposure/{asset_type}.json` × 8，每个 collector 一份。各 JSON 含 `asset_type`、`items[]`、`degraded`（布尔，标记该类是否降级运行）。
- 实现锚点：`scripts/exposure/collectors/*.py`（8 个 collector）+ `scripts/exposure/cli.py`（统一入口 `collect`）
- 状态：✅

### AR-04 综合产物合成
- 描述：把 8 份 collector 产物去重、合并，产出统一攻击面清单。
- 输入：`exposure/*.json`（AR-03 的 8 份产物）。
- 输出：`exposure/_summary.json`（8 类计数 + degraded 标记）+ `exposure_assets.json`（去重后的全量资产清单）。
- 实现锚点：`scripts/exposure/synthesizer.py` + `scripts/exposure/cli.py`（`synthesize` 子命令）
- 状态：✅

### AR-05 热点排序
- 描述：对全量资产按风险打分，取前 20% 作为高危热点。
- 输入：`exposure_assets.json`（AR-04 产物）。
- 输出：`hotspots.json`，含 `hotspots[]`（每项含 `fqn`、`risk_score`、`reasons[]`），长度约为全量资产的 20%。
- 实现锚点：`scripts/exposure/hotspot_ranker.py` + `scripts/exposure/cli.py`（`rank` 子命令）
- 状态：✅

### AR-06 端点排序优先级公式
- 描述：按公式给端点排优先级队列，决定 Phase 2 的入场顺序。无外部参数的端点 `base = -100` 直接降权；POST/PUT/DELETE `base = 10`；GET `base = 0`。最终分值 = `base + sink_count + preset_match * 10`。
- 输入：`hotspots.json`（AR-05 产物）+ 端点的 HTTP 方法与参数列表。
- 输出：`priority_queue.json`，含 `queue[]`（按分值降序，每项含 `endpoint`、`score`、`base`、`sink_count`、`preset_match`）。
- 实现锚点：`scripts/exposure/priority_calculator.py` + `scripts/chain/priority_calculator.py`
- 状态：✅

### AR-07 离线降级
- 描述：SSH 目标缺失时，env_filter 等 collector 标记为 degraded 并继续，不阻塞主流程。
- 输入：`ssh_target`（preset.json 字段，可为空）。
- 输出：对应 collector 产物 JSON 中 `degraded: true`，其余 collector 正常产出。主流程不中断。
- 实现锚点：`scripts/exposure/collectors/env_filter_collector.py`
- 状态：⚠️（降级 fallback 已实现，但 SSH 远程命令执行链路本身未经验证；degraded 模式下该类资产为空）

## Phase 2 — 调用链与 Sink

### AR-08 调用链构建
- 描述：对每个端点从 sink 反向回溯到入口，构建完整调用链。
- 输入：`priority_queue.json`（AR-06 产物）+ `codegraph.db`（SQLite）。
- 输出：每端点一条调用链，节点序列 `[entry_method, ..., sink_method]`，每节点含 `fqn`、`line`、`node_id`。链总数等于端点总数。
- 实现锚点：`scripts/chain/chain_builder.py`（902 行主入口）+ `scripts/chain/sqlite-extract-chain.py`
- 状态：✅

### AR-09 链文件格式
- 描述：把调用链按固定格式 `method:nodeid1->method:nodeid2` 落盘，供后续阶段加载。
- 输入：AR-08 产出的内存调用链节点序列。
- 输出：`{loop_audit_dir}/chains/{endpoint}.{method:nodeid1->method:nodeid2}.json`，文件名按端口/端点分组存储，内容含完整节点链。
- 实现锚点：`scripts/chain/chain_file_writer.py`
- 状态：⚠（模块已实现，120 行含 nodeid 格式，但尚未接入 chain_builder 主管线依赖图，独立运行未端到端打通）

### AR-10 sink 识别（预置 + 动态）
- 描述：预置约 80 个高危 sink（覆盖 SQL/RCE/LDAP/SpEL/NoSQL/XXE/反序列化/SSRF/路径穿越等 15 类）+ 动态识别所有非本 groupId 命名空间的外部调用。
- 输入：`codegraph.db` 中全部方法 FQN 列表 + 当前 `groupId`。
- 输出：sink 命中清单，含 `fqn`、`category`、`source`（`preset` 或 `dynamic`）。
- 实现锚点：`scripts/chain/sink_registry.py`（`PRESET_SINKS` 字典 15 类约 80 条 + `identify_dynamic_sinks()`）
- 状态：✅

### AR-11 优先级计算
- 描述：结合 sink 命中数与端点 base 分，计算链的最终优先级，决定 Phase 3 消费顺序。
- 输入：AR-08 调用链 + AR-10 sink 命中清单 + AR-06 base 分。
- 输出：更新后的 `priority_queue.json`，`queue[]` 按链级 score 降序，高危链排前部。
- 实现锚点：`scripts/chain/priority_calculator.py`
- 状态：✅

### AR-12 鉴权类缓存
- 描述：一次性识别并缓存鉴权类（Filter / Interceptor / 注解），后续判定不重复查询 codegraph。
- 输入：`codegraph.db` 中带鉴权注解的类与方法。
- 输出：Memurai 键 `{groupId}:auth_class:*`，值为鉴权类 FQN + 类型清单。后续阶段从缓存读取。
- 实现锚点：`scripts/chain/auth_class_cacher.py` + `scripts/redis/memurai_client.py`
- 状态：✅

## Phase 3 — AI 分析

### AR-13 前 5 层全量加载
- 描述：调用链前 5 层（depth < 5）一次性返回完整方法体，给 AI 充分上下文。
- 输入：调用链节点序列 + Memurai 缓存的方法体。
- 输出：前 5 层节点的完整方法体源码（含 fqn + line + body），后续层只返回 `node_id`。
- 实现锚点：`scripts/analysis/method_body_loader.py`
- 状态：✅

### AR-14 按需加载
- 描述：第 5 层之后只给 node_id，AI 通过 `load_by_node_id()` 按需拉取方法体。AI 可在污点已消除时主动跳过后续层。
- 输入：`node_id`（调用链节点标识）。
- 输出：对应节点的完整方法体源码。未拉取的节点保持空载，节省 token。
- 实现锚点：`scripts/analysis/method_body_loader.py`（`load_by_node_id()`）
- 状态：✅

### AR-15 加载次数追踪
- 描述：记录每个方法体被加载的次数，落 SQLite，供 Phase 4 效率评估。
- 输入：每次方法体加载事件（含 `chain_id`、`node_id`、`loads`、`cached`）。
- 输出：SQLite 表，含 `chain_id`、`loads`、`cached`、`ratio` 字段。可通过查询接口聚合。
- 实现锚点：`scripts/analysis/load_counter.py`
- 状态：✅

### AR-16 单链报告 + CVSS 4.0
- 描述：每条调用链组装一篇报告，含每节点污点标注、漏洞根因、PoC 构造思路、CVSS 4.0 评分。不含任何修复建议（硬约束）。
- 输入：调用链全节点方法体 + sink 命中 + 鉴权上下文（AR-12 缓存）。
- 输出：`{loop_audit_dir}/reports/api-audit/{chainId}.md`，含 fqn + line + 污点标注 + CVSS 4.0 评分 + payload 草稿。
- 实现锚点：`scripts/analysis/chain_report_generator.py`（含 `estimate_cvss_4`）
- 状态：✅

## Phase 4 — PoC 验证与收敛

### AR-17 PoC 三态
- 描述：PoC 验证结果分三态写回报告：是问题（确认漏洞）、非问题（证伪）、暂时无法确认（受环境限制）。不强制结论。
- 输入：Phase 3 报告中的漏洞判定 + PoC 环境（可达 / 不可达 / 受限）。
- 输出：`{loop_audit_dir}/routes/poc/{验证状态}_{问题等级}_{fqn.method-sink-roundNNN}.md`。验证状态枚举：是问题 / 非问题 / 暂时无法确认。
- 实现锚点：`scripts/audit/poc-monitor.py`（后台 daemon 轮询 Memurai 队列派发）
- 状态：✅

### AR-18 收敛判定 4-AND
- 描述：四项指标同时达标才允许终止 loop：平均分 ≥ 85、标准差 < 3、数据对账通过 ≥ 10 次、端点覆盖率 ≥ 0.95。
- 输入：当前轮次的 4 项指标（`avg` / `std` / `reconcile` / `coverage`）。
- 输出：布尔值，当且仅当 4 项同时达标返回 `True`，否则 `False` 触发新一轮。
- 实现锚点：`scripts/audit/self_evolution.py`（`calculate_convergence()`）
- 状态：✅

### AR-19 知识沉淀
- 描述：把本轮发现的自定义注解、已知消毒器、动态路由模式、finding 模式写入 `knowledge.json`，下一轮自动加载。
- 输入：本轮 findings + 新发现的消毒器与注解。
- 输出：Memurai 键 `{groupId}:knowledge:*` + `{loop_audit_dir}/knowledge.json`。下一轮经 `merge_knowledge_from_memurai()` 合并进上下文。
- 实现锚点：`scripts/audit/self_evolution.py`（`merge_knowledge_from_memurai()`）
- 状态：✅

### AR-20 评价指标极简化
- 描述：最终评价仅统计 6 个指标：`chain_method_count`（链方法总数）、`loaded_method_count`（实际加载方法数）、`vuln_chains`（漏洞链数）、`safe_chains`（安全链数）、`unknown_chains`（未判定链数）、`vuln_exposed_surface`（漏洞暴露面占比）。
- 输入：所有链的 `analysis_report.json`（AR-16 产物）+ `load_counter` 数据（AR-15）。
- 输出：`{loop_audit_dir}/round_metrics.json`，含上述 6 个字段。
- 实现锚点：`scripts/analysis/metric_simplifier.py`
- 状态：⚠️（脚本已落地，但当前输出的是单一 `loads/cached` ratio，未产出上述 6 指标 schema，需扩展输出字段）
