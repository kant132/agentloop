## 逐条实现

### 1. Phase 1 轻装

**修改位置**：`prompts/boss.md`
**实现**：Boss prompt 只包含端口扫描、Filter 发现、框架识别指令。明确禁止读文档、禁止威胁建模。
**验证**：Phase A 产出 project-context.json ≤ 3 分钟内。

### 2. 安全上下文合并缓存

**修改位置**：`prompts/supervisor.md`
**实现**：主管 prompt 要求先 `memurai-cli MGET` 批量加载 Filter 链和消毒器清单，再启动专家。
**验证**：漏洞分析阶段 0 次重复 Filter 查询（查 Memurai scan 日志）。

### 3. 漏洞发现与 PoC 解耦

**修改位置**：`scripts/audit/poc-monitor.py`（新建）
**实现**：独立 Python 进程，while 循环轮询 `finding:*:final` key，发现新 finished 调 2 个 poc-verify agent。
**验证**：主 loop 不等待 PoC，2 个 PoC agent 并发可观察。

### 4. 结构化自检

**修改位置**：`prompts/boss.md` 的 Phase D 章节
**实现**：Boss prompt 包含 if-then-else 自检清单（10-15 条），输出 JSON。
**验证**：每轮 `loop_audit/diag/self-check.json` 存在且 schema 合法。

### 5. 假阳率量化

**修改位置**：`prompts/boss.md` 的 Phase D 章节
**实现**：随机抽 30 条 finding 写入 `false-positive-samples.jsonl`，标注待人工。
**验证**：假阳率 > 30% 时 boss 输出警告并暂停派发新端点。

### 7. 调用链方法标注

**修改位置**：`prompts/analyst.md`
**实现**：分析师 prompt 要求对调用链每个方法输出 `{fqn, 业务意义, 分支逻辑, 参数传递影响}`。
**验证**：Memurai 中 `judgment:*` key 含完整标注。

### 8. 配置风险 SSH 检查

**修改位置**：`prompts/boss.md` 的 Phase B 章节
**实现**：Boss 调 ssh-skill 在环境中执行 `cat application.yml` + `ps aux | grep ...`，提取 csrf/session/token 配置。
**验证**：security-context.json 含 env_config 字段。

### 9. 硬编码凭证按需

**修改位置**：`prompts/expert-*.md`（所有专家）
**实现**：各专家 prompt 加一句："发现 password= / secret= / apiKey= 立即报，其他合规类不动"。
**验证**：finding 中 vuln_type=HARDCODED_CREDENTIAL 仅在证据显示可被外部利用时出现。

### 10. 项目知识跨轮次

**修改位置**：`prompts/boss.md` 的 Phase D + ralph-loop wrapper
**实现**：Boss 在 Phase D 从 `findings/` 提取模式，写入 Memurai `groupId.knowledge:*` key。wrapper 在每轮结束后把这些 key 合并到 knowledge.json。
**验证**：轮次 N+1 的 session 启动时能读到轮次 N 的知识。

### 11. 评分历史持久化

**修改位置**：`prompts/boss.md` 的 Phase D 章节
**实现**：Boss 在 Phase D 把本轮评分追加到 `loop_audit/diag/scoring-history.jsonl`。
**验证**：文件每轮增加 1 行。

### 12. 收敛客观标准

**修改位置**：`cross-agent-50r.py` 的 ralph-loop 调用
**实现**：`--completion-promise "loop_finished"`。Boss 在 Phase D 算方差和均分，达标则输出该短语。
**验证**：方差<5 均分>85 对账全过时 ralph-loop 主动停。

### 13. 有效优化持久化

**修改位置**：`prompts/boss.md` 的 Phase D 章节
**实现**：Boss 把本轮验证有效的优化建议追加到 `loop_audit/diag/optimization-suggestions.jsonl`。
**验证**：文件每轮可能增加条目。

### 14. 主 SKILL ≤50 行

**不修改 skill**。由 skill 维护 agent 处理。

### 15. rules ≤3 文件

**不修改 rules**。由其他 agent 处理。

### 16. 工具自生成脚本和知识

**修改位置**：`cross-agent-50r.py` 的轮次结束逻辑
**实现**：每轮结束时允许 boss 写入 `scripts/generated/` 目录，且必须带 `project_id` 字段避免污染。
**验证**：generated 目录下的脚本含所属 project_id。

### 17. 核心工具不可降级

**修改位置**：`cross-agent-50r.py` 的启动检查
**实现**：启动时检测 codegraph/ast-grep/memurai-cli 三件工具，任一不可用则 exit 1。
**验证**：禁用 Memurai 服务后启动 daemon 立即 exit 1。

### 18. 每步骤明确指定模板

**修改位置**：所有 `prompts/*.md`
**实现**：每个 prompt 明确写"产出到 [具体路径]"，不让 agent 自行选择。
**验证**：grep prompts/ 目录无歧义路径引用。

### 19. 端点枚举排序

**修改位置**：`prompts/boss.md` 的 Phase A 章节
**实现**：Boss prompt 含排序规则：先 grep sink 表，命中的排最前；然后按 POST/UPDATE/DELETE/GET 排；外部前缀排最前。
**验证**：实际审计 WebGoat 时，`/sqlinjection` 等含 sink 端点排在 `/login`（纯 POST 无 sink）之前。
