# 工作流（数据驱动版）

> 替代旧版。本版先定义数据格式，再描述流程。所有阶段产出的 JSON 必须符合本规范。

## 评价指标（仅 6 个）

| 指标 | 定义 | 理想值 |
|------|------|--------|
| chain_method_count | 调用链上的方法体总数 | — |
| loaded_method_count | 实际加载的方法体数 | < chain_method_count × 0.3 |
| vuln_chains | 确认有漏洞的调用链数 | — |
| safe_chains | 确认无漏洞的调用链数 | — |
| unknown_chains | 无法确认的调用链数 | 越少越好 |
| vuln_exposed_surface | 确认有漏洞的暴露面（端点）数 | — |

核心公式：`load_ratio = loaded_method_count / chain_method_count`，理想 < 0.3。其他冗余指标一律删除。

## 数据格式规范

每份 JSON 都给出字段语义与示例。下游脚本与 skill 按 schema 校验，不符即报错终止。

### 1. exposure.json（Phase 1 每个 collector 一个）

```json
{
  "asset_type": "route",
  "collected_at": "ISO8601",
  "source": "ast-grep",
  "stats": {"total": 0, "degraded": 0},
  "items": [
    {
      "fqn": "com.example.UserController#getUser",
      "http_method": "GET",
      "path": "/api/users/{id}",
      "has_external_param": true,
      "nodes_id": "method:abc123...",
      "sig_hash": "abc123...",
      "file": "src/...",
      "line": 10
    }
  ]
}
```

字段说明：`asset_type` 对应 8 类资产（route / config / codegraph / auth_code / sensitive_info / waf / db_schema / env_filter）。`stats.degraded` 标记 SSH 等缺失时降级采集量。

### 2. exposure_assets.json（Phase 1 综合）

```json
{
  "total_assets": 200,
  "by_type": {"route": 145, "config": 30},
  "by_risk": {"high": 50, "medium": 100, "low": 50},
  "assets": [],
  "dedup_report": {"before": 212, "after": 200, "removed": 12}
}
```

跨 collector 合并、去重、风险分级后的全量资产表。`dedup_report` 记录去重前后差异，便于追溯。

### 3. hotspots.json（Phase 1 热点排序）

```json
[
  {
    "fqn": "com.example.UserController#getUser",
    "risk": "high",
    "hotspot_score": 45,
    "sink_count": 2,
    "preset_sink_matches": 1
  }
]
```

取风险前 20% 作为 Phase 2 主输入。`hotspot_score` 由 sink 命中数、风险等级、参数可达性加权得出。Sink 模式表见 `skills/injection-audit`，不放本文档。

### 4. chains/{endpoint}.txt（Phase 2 调用链文件）

```
org.example.UserController#getUser:node1->org.example.UserService#findById:node2->org.example.UserRepo#query:node3
```

格式：`fqn:nodes_id` 节点，用 `->` 连接。一端点一文件，文件名按 AGENTS.md 的 Windows-safe 规则。每行一条链。

### 5. chain_data.json（Phase 2 链 + 优先级）

```json
{
  "endpoint": "GET /api/users/{id}",
  "entry_fqn": "org.example.UserController#getUser",
  "chains": [
    {
      "chain_id": "chain_001",
      "nodes": [{"fqn": "...", "node_id": "node1", "depth": 0}],
      "total_methods": 5,
      "sink_count": 2,
      "preset_sink_matches": 1,
      "priority": 22,
      "priority_breakdown": {"base": 0, "sink_count": 2, "preset_match": 20}
    }
  ],
  "total_chains": 1
}
```

`priority` 决定 Phase 3 的消费顺序。`priority_breakdown` 让优先级可解释、可调参。

### 6. analysis_report.json（Phase 3 单链报告）

```json
{
  "chain_id": "chain_001",
  "entry_fqn": "...",
  "verdict": "vuln",
  "verdict_options": ["vuln", "safe", "unknown"],
  "loaded_methods": 3,
  "total_methods": 5,
  "load_ratio": 0.6,
  "findings": [
    {
      "type": "SQL注入",
      "root_cause": "参数直接拼接到SQL",
      "entry_point": "GET /api/users/{id}",
      "payload": "1' OR '1'='1",
      "impact": "数据库全表泄露",
      "cvss_4": {"base_score": 9.1, "vector": "AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H"}
    }
  ],
  "method_analysis": []
}
```

`verdict` 三值枚举，对应 `vuln_chains` / `safe_chains` / `unknown_chains` 计数来源。`load_ratio` 直接汇总到轮次指标。`findings.type` 与 `payload` 由对应 expert skill 产出，prompt 不内联漏洞知识。

### 7. poc_result.json（Phase 4 PoC 验证）

```json
{
  "chain_id": "chain_001",
  "poc_status": "confirmed",
  "poc_status_options": ["confirmed", "denied", "inconclusive"],
  "payload_sent": "...",
  "response_evidence": "...",
  "executed_at": "ISO8601"
}
```

只有 `confirmed` 才计入 `vuln_chains` 与 `vuln_exposed_surface`。验证细节由 `skills/poc-verify` 决定，本文档不展开。

### 8. round_metrics.json（Phase 4 轮次评价指标）

```json
{
  "round": 5,
  "chain_method_count": 500,
  "loaded_method_count": 120,
  "load_ratio": 0.24,
  "vuln_chains": 8,
  "safe_chains": 45,
  "unknown_chains": 2,
  "vuln_exposed_surface": 6,
  "total_chains": 55,
  "total_endpoints": 145
}
```

`load_ratio` < 0.3 视为缓存策略有效。`total_chains` / `total_endpoints` 为参考分母，不计入 6 项核心指标。本文件驱动收敛判定。

## 流程（5 阶段 × 数据流）

每阶段只列输入、输出、脚本、产出 schema。审计知识、漏洞模式、prompt 模板不在本文档。

### Phase 0 — 准备

- 输入：`projects/{group_id}/preset.json`
- 输出：Memurai 清空 `{groupId}:*`，保留 `{groupId}:knowledge:*`
- 脚本：`scripts/audit/check_core_tools.py`，退出码 0 通过，任一工具缺失 exit 2 不降级
- schema：无

### Phase 1 — 暴露面采集

- 输入：Java 源码 + preset.json + codegraph.db（可选）+ SSH 远程目标（可选，缺失则降级）
- 输出：8 份 `exposure/*.json` + `exposure_assets.json` + `hotspots.json`
- 脚本：`python -m scripts.exposure.cli collect` → `synthesize` → `rank`
- schema：exposure.json、exposure_assets.json、hotspots.json

### Phase 2 — 调用链 + 优先级

- 输入：hotspots.json + codegraph.db
- 输出：`chains/{endpoint}.txt` + `chain_data.json` + Memurai 方法体缓存（key 见 AGENTS.md 路径占位符表）
- 脚本：`scripts/chain/chain_builder` + `chain_file_writer` + `sink_registry` + `priority_calculator`
- schema：chains/{endpoint}.txt、chain_data.json

### Phase 3 — AI 分析

- 输入：chain_data.json（按 `priority` 队列消费）+ Memurai 方法体缓存
- 输出：每链一份 `analysis_report.json`
- 脚本：`scripts/analysis/method_body_loader` + `chain_report_generator` + `load_counter`
- 约束：`load_counter` 记录每链实际加载方法数，超阈值即告警，目标 `load_ratio` < 0.3
- schema：analysis_report.json

### Phase 4 — PoC + 收敛

- 输入：analysis_report.json
- 输出：`poc_result.json` + `round_metrics.json` + `knowledge.json`
- 脚本：`scripts/audit/poc-monitor` + `self_evolution` + `metric_simplifier`
- 收敛：`metric_simplifier` 把每轮只保留 6 项核心指标，旧冗余字段丢弃
- schema：poc_result.json、round_metrics.json
