# 重构方向（优先级排序的行动清单）

> 基于 RFC-0001 实施后的现状审计、AGENTS.md Common Pitfalls、Karpathy 铁律综合得出。

## P0 阻塞性 / 已知 bug

P0 项处理已经影响功能正确性的缺陷。修复前不应启动新特性工作，否则知识沉淀、Windows 运行、测试导入、链路查询都会被这些问题污染。

### 1. 修复 self_evolution.py 的 suffix 路由 bug

- **现状**: `merge_knowledge_from_memurai` 的 `suffix` 参数硬编码为 4 个固定字符串（`pruning-log`、`coverage`、`findings`、`patterns`）。新增任何 knowledge 类型都无法被合并进沉淀库。
- **目标**: 改为基于前缀通配或动态注册的匹配，新增 knowledge 类型无需改源码即可合并。
- **工作步骤**:
  1. 为现有 4 个 suffix 写回归测试，锁定当前合并行为。
  2. 将 suffix 匹配逻辑从等值判断改为前缀匹配（`key.startswith(f"{groupId}:knowledge:")`）或从配置文件动态读取允许列表。
  3. 回归测试全部通过，并新增一个未注册 suffix 验证能被正确合并。
- **预期收益**: 避免知识沉淀在新增 knowledge 类型时静默丢失。
- **风险**: 低。已有测试覆盖，改动局部。
- **涉及文件**: `scripts/audit/self_evolution.py`

### 2. 修复 poc-monitor.py 在 Windows 下无法执行 opencode

- **现状**: `subprocess.Popen(['opencode'])` 在 Windows 下失败。Windows 上 opencode 实际是 `opencode.cmd` 批处理脚本，PATH 解析不会自动补 `.cmd` 后缀。
- **目标**: 跨平台稳定唤起 opencode，Linux/macOS 不受影响。
- **工作步骤**:
  1. 增加 Windows CI 测试用例，复现当前失败。
  2. 检测 `sys.platform`，Windows 下改为 `opencode.cmd` 或加 `shell=True`（需做命令注入审核）。
  3. 在 Windows 与 Linux 各跑一遍验证。
- **预期收益**: Windows 环境下 PoC 监控链路可用，跨平台一致性恢复。
- **风险**: 中。`shell=True` 可能引入命令注入，必须确认参数来源可信。
- **涉及文件**: `scripts/audit/poc-monitor.py`

### 3. 修复 conftest.py 引用已废弃中文路径"脚本"

- **现状**: `scripts/tests/conftest.py` 与 `test_scripts/conftest.py` 中 `sys.path.insert` 指向字符串 `"脚本"`，实际目录名是英文 `"scripts"`。导致测试套件 import 失败。
- **目标**: 全部改为 `"scripts"`，测试套件可正确 import。
- **工作步骤**:
  1. `grep` 全仓搜索 `"脚本"` 字面量引用。
  2. 替换为 `"scripts"`。
  3. 运行全量测试验证 import 链路恢复。
- **预期收益**: 测试套件能正确加载，CI 绿。
- **风险**: 低。纯路径替换。
- **涉及文件**: `scripts/tests/conftest.py`、`test_scripts/conftest.py`

### 4. 处理 sqlite-multi-hop-search.py（chain-sql-engine.md §3 标记"确认有问题"）

- **现状**: 20 层 LEFT JOIN 方案被设计文档明确标记为不可靠，但脚本仍存在并被部分逻辑引用。
- **目标**: 消除已知不可靠代码。二选一：若仍有调用方则迁移到 `chain_builder.py` 的 CTE 方案；若无调用则归档。
- **工作步骤**:
  1. grep 全仓确认是否仍有调用入口。
  2. 若无调用，移入 `scripts/deprecated/` 并加 README 说明废弃原因。
  3. 若有调用，逐处迁移到 CTE 方案，对比新旧输出一致性后删除旧文件。
- **预期收益**: 消除一个已知会产出错误结果的代码路径。
- **风险**: 中。若误判仍有调用会导致链路断裂，需调用关系核对完整。
- **涉及文件**: `scripts/chain/sqlite-multi-hop-search.py`、`scripts/chain/chain_builder.py`

## P1 架构改进 / RFC-0001 集成

P1 项推动代码向 RFC-0001 的 SOLID 架构收敛，并清理 skills/ 目录的结构性噪声。每项都需要端到端回归测试，避免审计结果漂移。

### 5. cross-agent-50r.py 接入新 exposure 管线

- **现状**: daemon 仍调用旧 `attack_surface_scanner.py`，未接入 RFC-0001 落地的 `scripts/exposure/` 模块。新旧管线并存。
- **目标**: daemon Phase 1 改为调 `python -m scripts.exposure.cli collect`，统一到 SOLID 架构。
- **工作步骤**:
  1. 加 feature flag（环境变量或 preset 字段）切换新旧管线。
  2. 集成测试对比新旧管线在同一 preset 下的输出差异。
  3. 差异可接受且收敛无回归后，默认启用新管线，旧扫描器降级为 fallback。
- **预期收益**: 攻击面发现逻辑统一到单一可维护入口，符合 RFC-0001。
- **风险**: 高。daemon 是核心入口，输出差异可能导致收敛指标偏移，需多轮回归。
- **涉及文件**: `scripts/audit/cross-agent-50r.py`、`scripts/exposure/cli.py`

### 6. 删除 skills/java-whitebox-loop/rules/ 下 7 个 DEPRECATED 旧规则文件

- **现状**: `01-*.md` 至 `07-*.md` 编号的旧版规则文件标记 DEPRECATED 但仍保留，造成认知噪声。
- **目标**: 移入 `_archive/` 或彻底删除，主目录只保留现行规则。
- **工作步骤**:
  1. grep 全仓确认无文件引用这 7 个文件。
  2. 移入 `skills/java-whitebox-loop/rules/_archive/`。
  3. 在 `_archive/` 加 `.agentsignore`，避免 skill 加载器扫描。
- **预期收益**: skills 目录减少 7 个干扰项，agent 加载更快更准。
- **风险**: 低。已标记 DEPRECATED。
- **涉及文件**: `skills/java-whitebox-loop/rules/01-*.md` ~ `07-*.md`

### 7. 消除 endpoint-supervisor 对不存在 skill 的悬空引用

- **现状**: `endpoint-supervisor/SKILL.md` 引用 `skills/call-chain-audit-thinking/SKILL.md`，该路径不存在。agent 加载时会跳过或报错。
- **目标**: 移除悬空引用，或将该能力显式落地为独立 skill。
- **工作步骤**:
  1. 确认 call-chain-audit-thinking 的能力当前如何实现（是否已合并进 endpoint-supervisor）。
  2. 决策：合并到 endpoint-supervisor（删引用），或创建独立 skill（补实现）。
  3. 修改 endpoint-supervisor/SKILL.md 的引用段落。
- **预期收益**: 消除 agent 加载歧义，调用链审计能力路径明确。
- **风险**: 低。文档级修改。
- **涉及文件**: `skills/endpoint-supervisor/SKILL.md`

### 8. 迁移 skills/arthas-audit/arthas-doc/（569 个离线文档文件）

- **现状**: arthas-doc 占 skills/ 总文件数约 96%，但内容只是 Arthas 官方文档的离线拷贝，不被代码逻辑使用。
- **目标**: 移到 `tools/arthas-doc/` 或改为按需下载，skills/ 目录大幅瘦身。
- **工作步骤**:
  1. 确认 `arthas_exec.py` 不依赖这些静态文件（grep import 路径）。
  2. 移动整个 `arthas-doc/` 目录到 `tools/`。
  3. 修改 SKILL.md 中对文档路径的引用，或改为运行时按需 fetch。
- **预期收益**: skills/ 目录瘦身 96%，降低 skill 扫描成本。
- **风险**: 中。若 arthas_exec 实际有路径依赖会断链，需先验证。
- **涉及文件**: `skills/arthas-audit/arthas-doc/**`、`skills/arthas-audit/SKILL.md`

## 实施建议

- **P0 优先**：4 项均不阻塞其他工作，建议在下一个迭代周期内全部完成。P0-1（suffix bug）和 P0-3（conftest 路径）改动最小，可先做。
- **P1 需端到端回归**：5 至 8 项都涉及架构收敛，每项完成后必须跑一次完整 audit preset 验证收敛指标无回归。P1-5（exposure 管线接入）风险最高，建议放最后。
- **P2/P3 渐进推进**：可分配到不同版本迭代，无需集中批次。P2-9（memurai 测试）与 P0-1 联动收益最大，建议同期做。
- **依赖关系**：P0-3 修复后 P2-11 的 conftest 指引才有意义；P1-8 完成后 P2-10 的 rules/ 拆分更顺。建议按依赖顺序排期。
- **不实施承诺**：本文档仅规划，任何字段变动需先更新本文档再启动实施，避免规划与执行脱节。
