# 威胁分析的本质：一个对抗论问题

> 本文试图回答：**威胁建模和漏洞扫描有什么根本区别？为什么 STRIDE 矩阵只是起点，不是终点？**

---

## 一、威胁分析不是「列清单」，而是「画地图」

### 1.1 当前做法的问题

	hreat-model-analyst/SKILL.md 的核心产出是：

1. STRIDE 矩阵（6 维度威胁分类）
2. 攻击树（从威胁反推攻击路径）
3. 数据流图（DFD）

这看起来完整，但有一个根本问题：**它把威胁分析变成了一个填空题。**

LLM 看到 STRIDE 矩阵，就会机械地填：
- Spoofing → 检查认证
- Tampering → 检查完整性
- ...

但真正的威胁分析不是填矩阵，而是回答一个更根本的问题：

> **如果我是一个攻击者，我会怎么攻破这个系统？我的最短路径是什么？**

### 1.2 威胁分析的本质：对抗性思维

威胁分析的本质是**对抗性思维**——你必须同时站在两个立场思考：

1. **防守者立场**：系统的设计意图是什么？安全措施在哪里？
2. **攻击者立场**：系统的弱点在哪里？最短突破路径是什么？

LLM 可以站在防守者立场（因为防守者的信息在文档和代码里），但很难站在攻击者立场（因为攻击者需要的信息是**缺失的**——你不知道什么安全措施**没有**被实现）。

### 1.3 威胁地图 vs 威胁清单

**威胁清单**（当前做法）：

`
1. SQL 注入 - 高风险
2. XSS - 中风险
3. 越权 - 高风险
...
`

这是一个**扁平的、无上下文的、无优先级的**列表。它不告诉你：
- 哪些威胁是相关的？（不是所有系统都有 SQL 注入风险）
- 哪些威胁是致命的？（有些威胁即使存在也不影响核心资产）
- 哪些威胁是攻击者的首选？（攻击者会选择最省力、最高回报的路径）

**威胁地图**（正确做法）：

`
攻击者视角：
  入口 → [认证绕过] → 普通用户权限 → [IDOR] → 他人数据
                    → [提权] → 管理员权限 → [RCE] → 服务器控制
  
防守者视角：
  入口 → [WAF] → [认证] → [鉴权] → [数据校验] → [日志审计]
              ↓         ↓         ↓           ↓
           已知绕过  JWT弱签名  Filter顺序错  部分漏检
`

威胁地图是**立体的、有上下文的、有优先级的**。它告诉你：
- 攻击者的最短路径是什么
- 防守者的薄弱环节在哪里
- 哪些威胁组合是致命的

## 二、STRIDE 的认知陷阱

### 2.1 STRIDE 是分类工具，不是分析工具

STRIDE 告诉你威胁可以分成 6 类，但它不告诉你：

1. **这 6 类威胁在你的系统中哪些是真实的？**
   - 一个内部系统可能没有 Spoofing 威胁（因为所有用户都已认证）
   - 一个只读系统可能没有 Tampering 威胁（因为没有写操作）

2. **这 6 类威胁之间的依赖关系是什么？**
   - Spoofing 往往是 Elevation of Privilege 的前提
   - Info Disclosure 往往是 Tampering 的前提（泄露的信息用于构造攻击）

3. **这 6 类威胁的回报和风险是什么？**
   - 攻击者会选择回报最高、风险最低的路径
   - 不是所有威胁都值得攻击者投入时间

### 2.2 STRIDE 的正确用法

STRIDE 应该是一个**检查清单**，确保你没有遗漏某个维度的威胁。但它不应该是一个**分析框架**——分析框架应该是攻击者的视角。

**正确用法**：

`
1. 先用攻击者视角画威胁地图（见下文）
2. 再用 STRIDE 检查是否有遗漏的维度
3. 最后用 STRIDE 的 6 个维度组织报告
`

**错误用法**（当前做法）：

`
1. 直接填 STRIDE 矩阵
2. 每个维度列出可能的威胁
3. 输出报告
`

## 三、威胁分析的四层认知

| 认知层次 | 描述 | LLM 能力 |
|---------|------|---------|
| **L1 枚举** | 列出所有可能的威胁 | ✅ 能做（但会过度枚举） |
| **L2 相关性** | 判断哪些威胁在这个系统中是真实的 | ⚠️ 部分能做 |
| **L3 组合** | 发现威胁之间的依赖和组合关系 | ❌ 几乎不能做 |
| **L4 对抗** | 从攻击者视角构造攻击链 | ❌ 完全不能做 |

**当前实现的 	hreat-model-analyst 停留在 L1-L2。** 它能列出威胁，能判断相关性，但不能发现威胁组合，更不能构造攻击链。

## 四、如何教 LLM 做真正的威胁分析

### 4.1 攻击者视角的威胁建模

**步骤 1：识别核心资产**

问：**攻击者想要什么？**

- 用户数据（PII、密码、支付信息）
- 系统控制权（RCE、管理员权限）
- 业务资源（免费商品、优惠券、余额）
- 拒绝服务（让系统不可用）

**步骤 2：识别攻击入口**

问：**攻击者从哪里进入？**

- 外部 API（REST、RPC、WebSocket）
- 用户输入（表单、文件上传、URL 参数）
- 第三方集成（OAuth、Webhook、回调）
- 内部接口（如果攻击者已经进入内网）

**步骤 3：识别信任边界**

问：**攻击者在哪里会遇到阻力？**

- 认证（登录、JWT、Session）
- 鉴权（RBAC、ABAC、ACL）
- 数据校验（输入验证、输出编码）
- 网络隔离（防火墙、WAF、VPN）

**步骤 4：构造攻击链**

问：**攻击者的最短路径是什么？**

`
攻击链 1：入口 → 认证绕过 → 普通权限 → IDOR → 他人数据
攻击链 2：入口 → SQL 注入 → 数据库 → 管理员密码 → 系统控制
攻击链 3：入口 → 文件上传 → Webshell → RCE → 服务器控制
`

**步骤 5：评估攻击链的可行性**

问：**每条攻击链的成本和回报是什么？**

| 攻击链 | 技术难度 | 时间成本 | 回报 | 可行性 |
|--------|---------|---------|------|--------|
| 链 1 | 低 | 低 | 中 | 高 |
| 链 2 | 中 | 中 | 高 | 中 |
| 链 3 | 高 | 高 | 高 | 低 |

### 4.2 信任边界分析

信任边界是威胁分析的核心概念。它不是网络边界，而是**权限边界**。

**常见信任边界**：

1. **未认证 → 已认证**：登录接口
2. **普通用户 → 管理员**：提权接口
3. **前端 → 后端**：API 接口
4. **外部网络 → 内部网络**：网关/防火墙
5. **应用层 → 数据层**：数据库访问

**每个信任边界必须回答**：

1. 边界在哪里？（代码位置）
2. 边界如何强制执行？（认证/鉴权/校验）
3. 边界可以被绕过吗？（已知绕过方式）
4. 边界被绕过的后果是什么？（影响范围）

### 4.3 威胁建模的产出

**当前产出**（	hreat-model-analyst/SKILL.md）：

1. STRIDE 矩阵
2. 攻击树
3. DFD
4. 模块分析

**正确产出**：

1. **核心资产清单**：攻击者想要什么
2. **攻击入口清单**：攻击者从哪里进入
3. **信任边界清单**：攻击者在哪里会遇到阻力
4. **攻击链清单**：攻击者的最短路径（按可行性排序）
5. **薄弱环节清单**：防守者的弱点在哪里

## 五、当前实现的批判

### 5.1 	hreat-model-analyst 的问题

**问题 1：STRIDE 是中心**

当前 skill 以 STRIDE 为中心组织分析，导致 LLM 机械地填矩阵，而不是从攻击者视角思考。

**改进**：STRIDE 应该是检查清单，不是分析框架。分析框架应该是攻击者视角。

**问题 2：缺少攻击链构造**

当前 skill 有攻击树，但攻击树是**从威胁反推路径**，不是**从入口正推路径**。攻击者不会先想「我要做 Spoofing」，而是想「我从哪里进入，然后怎么一步步达到目标」。

**改进**：增加「攻击链构造」步骤，从入口正推到核心资产。

**问题 3：缺少信任边界分析**

当前 skill 提到 DFD 中有信任边界，但没有深入分析每个信任边界的强制执行方式和绕过可能。

**改进**：增加「信任边界分析」步骤，每个边界必须回答 4 个问题（见上文）。

### 5.2 Phase 2 的问题

**问题**：Phase 2 的产出（威胁模型）和 Phase 5 的产出（漏洞发现）之间缺少明确的映射。

**改进**：Phase 2 的产出应该直接指导 Phase 5 的优先级：
- 攻击链中的节点 → Phase 5 的高优先级端点
- 薄弱环节 → Phase 5 的重点分析方向
- 信任边界 → Phase 5 的鉴权审计重点

---

## 六、一句话总结

**威胁分析的本质不是列清单，而是画地图——攻击者的地图。你必须站在攻击者的立场，想象他的最短路径、最高回报、最低成本。LLM 做不好这件事，因为它只会枚举，不会想象。修复方向不是写更多规则，而是教会 LLM 如何从攻击者视角思考。**
