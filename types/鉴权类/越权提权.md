# 越权提权

> **类型 ID**: `AP-AUTH-ESCALATION`
> **轨道**: FWD-B + FWD-C
> **业务域**: 9 类必查之一

## 一、定义

低权限用户通过修改请求中的角色/权限字段，获取高权限。

## 二、典型场景

### 2.1 角色由客户端传
```java
// ❌ 角色字段来自请求
@PostMapping("/register")
public User register(@RequestBody RegisterRequest req) {
    User user = new User();
    user.setUsername(req.getUsername());
    user.setRole(req.getRole());  // ❌ 客户端可传 "ADMIN"
    return userService.save(user);
}
```

### 2.2 修改请求中的 role
```java
// ❌ 修改用户信息时可改 role
@PutMapping("/users/{id}")
public User update(@PathVariable Long id, @RequestBody UserUpdateRequest req) {
    User user = userService.findById(id);
    if (req.getRole() != null) {
        user.setRole(req.getRole());  // ❌ 应禁止
    }
    return userService.save(user);
}
```

### 2.3 提权 API 缺鉴权
```java
// ❌ 提升权限的 API 自身无鉴权
@PostMapping("/users/{id}/promote")
public User promote(@PathVariable Long id, @RequestBody PromoteRequest req) {
    User user = userService.findById(id);
    user.setRole(req.getNewRole());
    return userService.save(user);
}
```

## 三、检测启发式

### 3.1 关键信号
- `setRole(...)` / `setAdmin(...)` / `setPermissions(...)` 出现
- 调用栈上能追溯到外部输入
- **缺失**：提权操作本身的鉴权（应是 admin only）

### 3.2 SQLite 特征
```sql
SELECT m.fqn, m.file, m.line FROM method m
WHERE m.body LIKE '%setRole%'
   OR m.body LIKE '%setAdmin%'
   OR m.body LIKE '%setPermissions%'
   OR m.body LIKE '%grantAuthority%'
```

## 四、缺失规则

| 操作 | 应有鉴权 |
|------|---------|
| 改自己 role | 不允许（仅 admin 可改） |
| 改别人 role | admin only |
| 提权 API | admin only + 二次确认 |
| 注册时设 role | 不允许（默认普通用户） |
