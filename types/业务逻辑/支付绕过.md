# 支付绕过

> **类型 ID**: `AP-BIZ-PAYMENT`
> **轨道**: FWD-C
> **业务域**: 9 类必查之一（金融场景必查）

## 一、定义

支付流程中，业务规则未在服务端强制执行，导致攻击者绕过支付、篡改金额、重复支付等。

## 二、典型场景

### 2.1 金额客户端控制
```java
// ❌ 金额由前端传入
@PostMapping("/order/pay")
public Result pay(@RequestBody PayRequest req) {
    return payService.pay(req.getOrderId(), req.getAmount());  // amount 可被篡改
}
```

### 2.2 订单不校验
```java
// ❌ 不校验订单归属与金额
@PostMapping("/order/confirm")
public Result confirm(@RequestBody ConfirmRequest req) {
    Order order = orderService.findById(req.getOrderId());
    if (order.getStatus() == "PAID") return fail;
    return payService.complete(order);
}
```

### 2.3 状态机绕过
```java
// ❌ 状态字段由前端控制
@PostMapping("/order/ship")
public Result ship(@RequestBody ShipRequest req) {
    Order order = orderService.findById(req.getOrderId());
    order.setStatus("SHIPPED");  // 没校验前置
    return orderService.save(order);
}
```

## 三、检测启发式

### 3.1 关键信号
- 端点含 `pay` / `order` / `payment` / `amount` / `price` / `total`
- 接收的金额/状态字段来自请求体
- **缺失**：服务端从订单 ID 重新查金额

### 3.2 AST 模式
```yaml
pattern: $SERVICE.pay($ORDER_ID, $AMOUNT)  # amount 是变量
# 缺：$SERVICE.pay($ORDER_ID, $ORDER.AMOUNT)  # amount 是 DB 查出来的
```

## 四、缺失规则

| 操作 | 必需校验 |
|------|---------|
| 创建订单 | 服务端算金额（不取请求体 amount） |
| 支付回调 | 校验回调签名 + 服务端从 DB 取金额 |
| 状态推进 | 校验前置状态合法 |
| 退款 | 校验订单已支付 + 金额不超原订单 |

## 五、业务影响

**致命**（金融场景）— 直接资金损失

## 六、PoC 模板

```json
// 篡改金额
{"orderId": 123, "amount": 0.01}    // 实际订单 100 元

// 负数
{"orderId": 123, "amount": -100}

// 跳过支付
POST /api/order/confirm
{"orderId": 123, "status": "PAID"}  // 直接置为已支付

// 并发（条件竞争）
10 个并发请求扣款，可能多次扣款
```
