# 必读 01：避免重复劳动

> **目的**：让 agent 不要做已做过的工作。**Memurai** 批预取 + sha256 自指 + 跨轮次缓存是核心机制。
>
> Memurai 走 `C:\Program Files\Memurai\memurai-cli.exe`（不再依赖 `pip install redis`）。

## 一、三层防重复

| 层 | 机制 | 检查时机 |
|---|------|---------|
| **L1 跨 subagent** | Memurai 预取全链方法 → 同链 4 个 FWD 共享 | subagent 启动前 |
| **L2 跨轮次** | `:finding:{chainId}` 状态查询 → 已 final 不重审 | 编排每轮前 |
| **L3 跨项目** | 全局类型库（`types/`）→ 通用模式不再发现 | 启动时加载 |

## 二、具体规则

### 2.1 方法体读取
- **必须先查 Memurai** `{groupId}:method:{fqn}#{startline}`
- 命中即用，**未命中也不查 codegraph**（codegraph 只构建调用拓扑，不取方法体）—— 应在调用链构建后、AI 分析前由 JAR + 源文件一次性预取，缺失说明预取失败，需触发回填而非兜底读
- TTL：**无**（session 结束 hook 自动清理，保留 `knowledge:*`，合并 `errors:log` 高频项到 `knowledge:errors`）
- 缓存只在活跃审计期间有效；下轮 session 启动时已是空状态
- 读 Memurai 走 `scripts/redis/memurai_client.py` 包装的 `memurai-cli GET`
- **铁律**：禁止直接 `Read` 整文件读方法体；禁止查 codegraph 拿方法体；方法体来源只能是 `tools/javaparser/java-method-call-extractor-1.0.0.jar` + 源文件预取

### 2.2 finding 状态
- 启动新轮前查 `{groupId}:finding:{chainId}`
- 状态为 `final` → 跳过
- 状态为 `draft` → 读取草稿继续评分
- 状态不存在 → 全新分析

### 2.3 自定义规则
- 发现新 sink AST 模式、新业务规则模板、新鉴权绕过模式 → **先查全局类型库**
- 命中相似（相似度 > 0.7）→ 复用并增量更新
- 不命中 → 写入 `types/` 跨项目索引

### 2.4 sha256 自指
- 每个 finding、每条规则、每个 type definition 头部带 sha256
- 比较前先比对 sha256，相同即认为等价
- 不同 → 取较新时间戳，旧的标记 `superseded`

## 三、违反的代价

- 重复读同一方法 = 浪费 token（单方法可达 500 tokens）
- 重复分析同一 finding = 浪费 5-10 分钟 subagent 时间
- 重复发现同一类型 = 污染类型库

## 四、自检方法

```bash
# 每轮结束统计
python scripts/audit/coverage-audit.py --stats
# 输出：重复读率 / 重复分析率 / 缓存命中率
# 任何一项 > 30% → 触发优化
```

## 五、反例

❌ subagent 启动后 Read 整文件读方法
❌ 新一轮 Loop 重新分析已 final 的 finding
❌ 重新发现已在 `types/SQL注入.md` 中的模式
