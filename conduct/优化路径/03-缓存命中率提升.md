# 优化路径 03：缓存命中率提升

> 缓存命中率高 = 重复劳动少 + token 少 + 速度快。

## 一、命中率基线

- 健康：> 70%
- 警告：50-70%
- 异常：< 50%

## 二、Memurai key 设计原则

### 2.1 必带前缀
- `audit:{groupId}:commit:{commitHash}:` — 避免跨项目污染 + 代码变更自动失效
- 全局共享类型不带 groupId

### 2.2 粒度选择
| 数据 | 粒度 | key 示例 |
|------|------|---------|
| 方法体 | 单方法 | `:method:{fqn}#{sigHash}` |
| 调用链 | 整链 | `:chain:{chainId}` |
| 判定结果 | 单方法+判定器 | `:judgment:{fqn}#D{N}` |
| finding 草稿 | 单 finding | `:finding:{chainId}:draft` |
| finding 终稿 | 单 finding | `:finding:{chainId}:final` |
| 预取 | 整链 | `:prefetch:{chainId}` |

### 2.3 TTL 选择
| 数据 | TTL | 理由 |
|------|-----|------|
| method | 24h | 稳定 |
| chain | 1h | 迭代期短 |
| judgment | 1h | 跟着 chain |
| finding draft | 30 轮 | 防永久滞留 |
| finding final | 永久 | 落盘后只读 |
| env | 1h | 环境会变 |

## 三、批预取模式

**subagent 启动前**：
```python
def prefetch_chain(chain: List[Method]) -> None:
    """一次 memurai-cli MSET 写入，避免 subagent 多次 GET"""
    key_value_pairs = {
        f"audit:{gid}:commit:{ch}:method:{m.fqn}#{m.sig_hash}": m.body
        for m in chain
    }
    # 走 scripts/redis/memurai_client.py 的 mset() → 一次 memurai-cli MSET k1 v1 k2 v2 ...
    memurai.mset(key_value_pairs)
    # 单独存一个 chain 总览，便于 subagent 启动时一次性拿全
    memurai.setex(f"audit:{gid}:commit:{ch}:prefetch:{chain_id}", 3600, chain_summary)
```

**subagent 启动时**：
```python
chain_summary = memurai.get(prefetch_key)  # 一次 memurai-cli GET
for m in chain_summary["methods"]:
    body = memurai.get(method_key(m))  # 必命中
```

## 四、跨轮次复用

- final finding 永久保留
- 启动新轮前先查 `audit:{gid}:commit:{ch}:finding:{chainId}:final`（`memurai-cli GET`）→ 跳过已 final 的链
- 节省：第二轮 50%+ 链无需重跑

## 五、跨项目复用

- 全局类型库不带 groupId → 所有项目共享
- subagent 启动时一次加载 → 后续调用 0 IO
- 命中率几乎 100%

## 六、命中率统计

```python
# 每轮结束统计
audit:stats:cache-hit-rate:{type}     → 各类缓存命中率
audit:stats:false-negative-rate        → 漏报率（与人工对比）
audit:stats:write-promotion-count      → 落盘次数
```

## 七、命中率低的原因

| 原因 | 检测 | 解决 |
|------|------|------|
| **key 粒度过细** | 同方法多次 GET | 改批预取 |
| **TTL 太短** | 跨轮次 miss | 延长 TTL |
| **commit 切换频繁** | commit 维度 miss | 增量加载 |
| **拼写不一致** | 同语义不同 key | 规范化 key |
| **commit hash 误用** | 全 miss | 检查 git rev-parse |

## 八、优化回路

```
命中率 < 50%
  │
  ├→ 启用批预取
  │
  ├→ 延长 TTL
  │
  ├→ 规范化 key
  │
  └→ 修正 commit hash 获取
```
